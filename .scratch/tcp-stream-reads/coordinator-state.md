Behavior implemented: `NetConfig` read deadline default 5s and raw cap default 1 MiB; accepted and outgoing streams inherit them. Reads run over nonblocking sockets without holding the state mutex, optional script timeout only shortens the host deadline, close clears shared socket/quota then shuts down outside the lock, and errors preserve operation/target/I/O kind/partial bytes. Unchecked mode retains the host cap; no_index retains string methods and omits blobs. No write API added.

## Accepted design and initial RED

Design approved before implementation: `read_blob/string(length[,timeout_ms])`, `read_to_end_blob/string(max_bytes[,timeout_ms])`; negative invalid, zero empty, positive reads return available short prefix/EOF empty; bounded EOF loops report partial progress. Optional timeout must be positive and may only shorten the finite host timeout. Raw receive cap is min(host, nonzero Engine limit); do not divide by three. If lossy output exceeds Engine string limit, return catchable ResourceLimit with consumed raw `partial_bytes`. All results were validated through Rhai Engine, registered package, and real TCP peers. The only actual RED is launch 1: before implementation, the contract test failed because `read_string (NetStream, i64)` was unregistered. Exact log: `red.log`.
