# Project-local runner custody adapter

`run_scoped.py` is a local copy of the shared runner with its hidden `_supervise`/`Popen` child path removed. It requires a custodian-provided nonblocking Unix `SOCK_DGRAM` endpoint, a custodian-precreated runtime and `tmp`, and a finite timeout no greater than the custodian cap. It sends bounded JSON datagrams and receives three data-pipe descriptors with `SCM_RIGHTS`. The runner drives overlapping stdin/stdout/stderr activity and reports worker joins; it never falls back to local child spawning.

The source-level XNU protocol check is recorded in `evidence/retry-design.md`: the current local protocol table registers stream and datagram sockets but not `SOCK_SEQPACKET`. Native host applicability and `SCM_RIGHTS` behavior still require execution after review.

`custodian.py` directly `posix_spawn`s and records the runner, workload group leader, same-group anchor, holder and sentinel. It remains the sole spawner and reaper. After complete readiness, the controls are:

- `normal`: overlapping 2 MiB stream round-trip (runner status 0), then group closure while the anchor still pins identity.
- `cancel`: held output pipes after workload exit, followed by cooperative worker cancellation and join (runner status 1).
- `assert`: custodian verifies leader, anchor, holder and sentinel are live, injects a deliberate runner assertion while all I/O workers are active, then reads back cleanup (runner status 86).
- `timeout`: the fixture drains and echoes the first 1 MiB, allowing both stream checkpoints and PID/PGID readiness; it then stalls while the runner's final input segment is withheld. The copied runner's own 8-second timeout reports status 124 and three joined workers after custodian scope closure.
- `term` and `kill`: the custodian verifies the live resource set and sends SIGTERM or SIGKILL to the runner; it checks exact signal wait statuses -15 or -9, then independently closes the managed workload scope.

The accepted caps are a 30-second case/session, a 5-second exact-child reap window, a 10-second outer cleanup allowance (45 seconds total), no more than 10 directly owned children, no more than 6 I/O workers, and 15 minutes total custody time including cleanup. Cleanup sends one SIGKILL to the managed group only while its unreaped leader is owned and the same-group anchor is observed live; it does not TERM the anchor before a later group signal. Assertion and runner-timeout controls first ask the custodian to close the scope while workers remain live, then join workers and return their distinct expected statuses. The assertion control records and validates an injection-time snapshot of all three active worker threads before releasing the deliberate failure; timeout readiness requires both stream checkpoints and the complete bounded stderr identity line. The custodian attempts exact-child cleanup and receipt readback after each control. The outer controller independently reads back both the quiescence record and matching receipt before removing a runtime. If the outer bound expires without a complete quiescence record, it writes an incomplete-cleanup record, retains the runtime, and leaves the live custodian as resource owner. Darwin Python versions without `os.waitid` use a bounded ctypes adapter matched to the Xcode 27.0 `MacOSX.sdk` (`macosx27.0`) `sys/signal.h` and `sys/wait.h` declarations. This source-level layout and flag match was checked on Darwin 27 arm64; the adapter requires a 104-byte `siginfo_t` and rejects other layouts. The pre-child capability check resolves the native `waitid` symbol, ABI layout, flags, and required POSIX/socket primitives before the custodian spawns its runner or workload children. Other SDK/architecture combinations require separate source review. Custodian-failure recovery is not claimed.

The custodian invokes the binary only with explicit `--fixture stream`, `--fixture stall`, or `--fixture anchor` arguments. Never invoke the historical bare Rust entry point: its default main still contains older unsafe process experiments. This source remains unexecuted. The coordinator source gate must approve the complete adapter before a native build or fixture launch. Native macOS `waitid`/`SCM_RIGHTS` behavior, interruption ordering, worker joins, and cleanup receipts still require the bounded live proof. Rust 1.77.2/MSRV and non-macOS behavior remain unverified.
