# Project-local runner custody adapter

`run_scoped.py` is a local copy of the shared runner with its hidden `_supervise`/`Popen` child path removed. It requires a custodian-provided nonblocking Unix `SOCK_DGRAM` endpoint, a custodian-precreated runtime and `tmp`, and a finite timeout no greater than the custodian cap. It sends one capped JSON request datagram and receives one capped result datagram. The custodian transfers exactly three data-pipe descriptors with `SCM_RIGHTS`. The runner drives bounded overlapping stdin/stdout/stderr activity on those descriptors; it never falls back to local child spawning. The private runtime remains owned by the custodian through cleanup receipt readback and exact removal.

The source-level XNU protocol check is recorded in `evidence/retry-design.md`: the current local protocol table registers stream and datagram sockets but not `SOCK_SEQPACKET`. Native host applicability and `SCM_RIGHTS` behavior still require execution after review.

`custodian.py` is an unexecuted source draft. It directly `posix_spawn`s and records the runner, workload group leader, same-group anchor, holder and sentinel, transfers pipe endpoints, reacts to a live-I/O event with normal/TERM/SIGKILL controls, retains the workload leader through group closure, exclusively observes/reaps direct PIDs, and writes/reads back a receipt. Client descriptor parsing and workload PID/PGID readiness precede interruption controls; cleanup attempts all recorded PIDs and marks incomplete receipts as failures. The source gate remains closed: outer-controller SIGKILL of its sole custodian can strand custodian-owned children, and no independent exact-child reaping authority has been established. Receipt/runtime cleanup and native macOS API behavior also require review. No build or process launch has validated this code.
