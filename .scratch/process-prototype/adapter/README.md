# Project-local runner custody adapter

`run_scoped.py` is a local copy of the shared runner with its hidden `_supervise`/`Popen` child path removed. It requires a custodian-provided nonblocking Unix `SOCK_DGRAM` endpoint, a custodian-precreated runtime and `tmp`, and a finite timeout no greater than the custodian cap. It sends bounded JSON datagrams and receives three data-pipe descriptors with `SCM_RIGHTS`. The runner drives overlapping stdin/stdout/stderr activity and reports worker joins; it never falls back to local child spawning.

The source review and XNU protocol check are recorded in `evidence/retry-design.md`. Darwin 27 arm64 native execution confirmed the approved `SOCK_DGRAM`/`SCM_RIGHTS` path. `custodian.py` is the sole spawner and reaper for the runner, workload group leader, same-group anchor, holder and sentinel. Before spawning, it validates the native `waitid` symbol, ABI layout, flags, and required POSIX/socket primitives. Darwin Python versions without `os.waitid` use a bounded ctypes adapter matched to the Xcode 27.0 `MacOSX.sdk` (`macosx27.0`) `sys/signal.h` and `sys/wait.h` declarations; this source-level layout and flag match was checked on Darwin 27 arm64, and the adapter requires a 104-byte `siginfo_t`. Other SDK/architecture combinations require separate review. Custodian-failure recovery is not claimed.

Coordinator source review approved candidate `9bf32e45d770ce3b021ac7e8f333d0d2bbe11501` before the current bounded native run. The custodian invoked only explicit `--fixture stream`, `--fixture stall`, and `--fixture anchor` modes. Never invoke the historical bare Rust entry point: its default main still contains older process experiments.

The six project-local controls passed on Darwin 27.0 arm64 with Rust/Cargo 1.93.0. Receipts are `evidence/custodian-88024-normal.json`, `custodian-93052-cancel.json`, `custodian-91927-assert.json`, `custodian-92369-timeout.json`, `custodian-92635-term.json`, and `custodian-92930-kill.json`. Normal/cancel verified exact 2 MiB input/stdout/stderr contents and three worker joins; cancel retained an output pipe through workload exit. Assertion returned 86 after an injection-time three-worker live/active/held/acknowledged snapshot. The runner's own timeout returned 124 after three workers joined, with all managed resources live before cleanup. Runner TERM and KILL produced their exact signal wait statuses; worker joins after those abrupt interruptions are not claimed. Every receipt records exact child statuses and descriptor closure; controller readback matched the quiescence receipt before exact runtime removal. The coordinator independently checked hashes, recorded PIDs and runtime absence.

Caps were a 30-second case/session, a 5-second exact-child reap window, a 10-second outer cleanup allowance (45 seconds total), at most 10 directly owned children, at most 6 I/O workers, and at most 15 minutes total custody including cleanup. Cleanup sends one SIGKILL to the managed group only while its unreaped leader is owned and same-group anchor is observed live. The assertion and runner-timeout controls keep workers live until scope closure, then join and report distinct expected statuses. Timeout receipt does not serialize the prior stream checkpoints/readiness identity, and the normal receipt does not separately serialize the anchor PGID; the approved protocol validated these before continuing, as detailed in the root README and `coordinator-state.md`. If the outer bound expires without a complete quiescence record, the controller retains runtime and leaves the live custodian as resource owner. No successful custodian-failure recovery is claimed.

The shared-runner `--timeout` status propagation control is recorded in `evidence/shared-runner-timeout.txt`; it does not prove private-scope cleanup. Earlier attempts, failed source reviews, actual execution history, and exact continuation budgets are preserved in `evidence/correction-attempt.md`. Rust 1.77.2/MSRV, non-macOS behavior, and production Rhai behavior remain unverified.
