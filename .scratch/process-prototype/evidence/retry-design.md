## Custody topology

Use the shared `/Users/hoppworks/projects/agent-skills/tools/run_scoped.py` unchanged for the Rust build only. Export the exact executable and source into a project-owned run directory before that scoped invocation exits. The fixture runtime, logs, and receipts are separately owned by the project-local custodian and never placed in the shared runner's deletion domain.

For the interruption controls, a foreground project-local custodian process is the only proof-resource spawner and reaper. Its invoking controller retains the exact custodian `Child`, enforces an outer monotonic deadline, and reads the final receipt before reaping it. Before any fixtures exist, the custodian creates and validates its run directory, evidence destination, control socket, deadline, fixed child slots, and cleanup protocol, then publishes READY. No workload is spawned before READY.

The subject of the interruption control is a project-local copy of `run_scoped.py` at `adapter/run_scoped.py`. The copy must retain its runner entry/timeout behavior but replace the hidden `_supervise`/`Popen` fixture-spawn path with an explicit broker protocol. Use a capped Unix `SOCK_DGRAM` socketpair with one bounded JSON frame per datagram and `SCM_RIGHTS` for the three data pipes; do not depend on `SOCK_SEQPACKET`, which is not registered by the current XNU local-protocol table ([Apple XNU `uipc_proto.c`](https://raw.githubusercontent.com/apple-oss-distributions/xnu/main/bsd/kern/uipc_proto.c)). The runner copy actively drives the fixture I/O through these descriptors; it is not a no-op stand-in. Broker requests are executed by the custodian, which directly spawns and immediately records each workload, anchor, pipe-holder, and sentinel PID before another fallible operation. The custodian owns every PID it signals and every status it reaps. No fixture may spawn descendants. The runner copy itself is also an exact direct child of the custodian, so the custodian can interrupt and reap it while the workload resources are live. If this active client/broker implementation cannot be made explicit and source-reviewable, do not run fixtures; this is a source gate, not permission to substitute the stock runner topology.

The custodian is single-threaded, uses bounded nonblocking protocol operations and monotonic polling, and is the sole reaper. It owns an exclusive runtime authority record with device/inode identity, rejects symlink/replacement, writes bounded durable evidence outside the inner runner, atomically publishes a cleanup receipt, reads it back, then removes only its exact temporary runtime. Failure to terminate or reap by deadline retains runtime/evidence and records incomplete cleanup. Control EOF supplements (but does not replace) finite deadlines.

## Identity and cleanup

Spawn the workload with `process_group(0)` so the group exists before fixture code; retain its exact `Child` immediately. Parse a complete first-code PID/PGID record, verify equality, and hold the workload behind a gate until the custodian has registered all required children and the same-group anchor has independently reported the expected PGID. The custodian alone signals the private group while retaining the unreaped leader handle. It never signals a reaped numeric group ID and never uses `kill(pid, 0)` as identity proof.

For normal workload exit, poll `waitid(P_PID, ..., WEXITED | WNOWAIT | WNOHANG)` with zeroed `siginfo_t`; handle no-event and errors distinctly. Keep leader and anchor unreaped through the final group signal, then reap each exactly once through the custodian. No `try_wait`, generic reaper, competing `wait`, `SIGCHLD=SIG_IGN`, `SA_NOCLDWAIT`, alarm handler, or alternate reaper is permitted. Native macOS proof must first verify the relevant `waitid` behavior and identity lifetime. If it fails, stop; do not fall back to stale PID signaling.

The harness owns its nonblocking I/O workers and joins them cooperatively on the passing cancellation case. Every operation has a case deadline and bounded work per wakeup. On exceptional failure, the custodian asks the runner/harness to stop, waits only to a grace deadline, then terminates/reaps exact child handles. It reports actual worker joins separately from harness-process termination; killing a harness cannot be called a successful join. Cleanup continues through individual errors and the receipt records every exact status. The outer controller may use its exact-custodian `SIGKILL` fallback only after reading an identity-checked quiescence record showing runner, workload leader, anchor, sentinel, and any holder exactly reaped with no cleanup errors. Without that record it must not signal or remove the runtime; retain it and fail closed.

The stream sends a first input segment, waits for a complete child output checkpoint, then sends final input and EOF. The payload exceeds pipe capacity, output streams use distinct deterministic transforms, and byte counts/checksums are asserted. This is an ordering proof of overlapping stdin/stdout/stderr activity, not a scheduler timing claim. A separately owned holder keeps an output pipe open through post-exit cancellation; it is a holder, not an escaped-descendant ancestry claim.

## Required controls after source review

With live workload, anchor, holder, sentinel, and I/O workers, run a live-resource assertion failure, a timed runner-copy interruption, and an abrupt `SIGKILL` of the runner-copy child. In each, keep the custodian alive, verify its exact runner/fixture statuses, worker result classification, sentinel preservation until sentinel's own cleanup, durable receipt readback, and no remaining owned process resources. Also prove normal direct exit plus safe managed-group closure while identity remains valid, post-exit I/O cancellation with the held pipe, and a passing overlapping-I/O control. A separate real shared `run_scoped.py --timeout` control verifies status propagation only; it does not prove private-scope cleanup.

The local adapter must itself have source-level tests/review demonstrating that every broker spawn is custodian-owned, that runner interruption cannot hide a child, that all passed descriptors close in the intended owner, and that the custodian's outer parent can collect its exit. The whole runner/custodian path has bounded case, cleanup, and outer deadlines. The source gate must set exact time/resource limits before launch; no launch count is assumed by default. No process launch occurs before the independent review.

## Limits

Claims, if later proven, apply only to the executed native macOS host and toolchain. Rust 1.77.2/MSRV behavior, Linux/Windows, escaped-descendant ancestry, production Rhai behavior, output/deadline policy, and release matrix remain open. Neither the historical logs nor this design establish those claims.
