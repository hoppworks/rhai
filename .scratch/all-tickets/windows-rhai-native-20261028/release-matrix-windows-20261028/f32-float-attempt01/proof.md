# Native Windows Rust 1.77.2 f32 float profile

This is a scoped release-matrix result for `testing-environ,sys,net,f32_float` on the native Windows 11 Pro guest, version `10.0.26300` (build `26300`), VM UUID `dc5b8fd5-1a0b-4d86-8b8f-aaa1bd492b19`. The [same-session OS and absent-scope readback](scope-absent.png) identifies the guest. The selected product source is fork-main `eea5ef8b8cf34b3d60b7b4b34a6211e9927e5c7e`; all 448 archived source entries were checked byte-for-byte against that checkout and the manifest. The reused archive originated from `7019821...` plus the now-committed Windows test overlay; its selected source tree remains unchanged. Archive SHA-256 `0005b38a...`, source manifest `254d0215...`, lock `12084a90...`, exact media inputs and ISO SHA-256 `767071d0...` appear in [binding](binding.json).

The accepted native `ScopedRunner.exe`/`MonitorAcceptanceDriver.exe` binaries and retained Rust/Cargo 1.77.2 guest toolchain were reused under pinned hashes and original finite lifetimes. The first preparation discovered a stale exact-scope pin in the copied cleanup helper; it was corrected and independently rechecked before any native launch. One ISO assembly command stopped before launch because media inputs had been staged at the wrong directory level; the same attempt's own stage was corrected. The final eight-input ISO was built with the scoped POSIX runner and independently read back. Guest preflight found zero parse errors in all three PowerShell inputs ([parser result](parser-result.png)), confirmed the new scope absent and OS version, and showed the [typed hash-guarded dispatch](dispatch-typed.png). The [immediate host preflight](host-dispatch-preflight-final.json) verified VM UUID, attached ISO bytes, preserved foreign `sdb`, the original serial inode/offset, free capacity and unexpired public build before the single Enter.

Inside one supervised Job, `RunRhaiContract.cmd` used a private Cargo home/target and `--locked`, then compiled these 12 integration targets with `cargo test --features testing-environ,sys,net,f32_float ... --no-run` (exit 0): `combined_sys_net`, `sys_env`, `sys_fs`, `sys_policy`, `net_connect`, `net_listen`, `net_reads`, `net_writes`, `net_metadata`, `sys_process`, `sys_process_report`, `sys_process_windows`. The exported versions are `rustc 1.77.2 (25ef9e3d8 2024-04-09)` and `cargo 1.77.2 (e52e36006 2024-03-26)`. The original [compile log](original-export/run/.scoped-evidence-88318d48ccd84697b26ca0af3c3f08c8/runtime/compile.log) lists all targets.

`RHAI_COMBINED_WRONG_EXPECTATION=1` made the public Engine/SysPackage/NetPackage test fail with Cargo 101 at the fresh host-file assertion (`filesystem-payload` versus a deliberately incorrect expected value). `RHAI_NET_F32_WRONG_TIMEOUT_EXPECTATION=1` made `f32_float_timeout_arguments_reject_fractional_and_non_finite_values` fail with Cargo 101 at its intended assertion after a real TCP peer delivered `Z`; the test checks fractional, NaN, infinite and extreme timeout arguments and that the valid read still receives the independent peer byte. After both switches were cleared, the restored 12-target suite exited 0: **126 passed, 0 failed, 0 ignored**. `net_reads` ran eight tests and `sys_process_windows` ran 32. `net_metadata` and Unix-only `sys_process` each ran zero tests; no behavior is inferred from those targets. The combined case uses a real Rhai script, fresh host-file read and independent TCP peer; native process cases use child-written records and exact-handle lifecycle checks. The two controls calibrate only their named assertions. Original [combined RED](original-export/run/.scoped-evidence-88318d48ccd84697b26ca0af3c3f08c8/runtime/combined-wrong.log), [f32 timeout RED](original-export/run/.scoped-evidence-88318d48ccd84697b26ca0af3c3f08c8/runtime/f32-timeout-wrong.log), [suite](original-export/run/.scoped-evidence-88318d48ccd84697b26ca0af3c3f08c8/runtime/suite.log) and [Driver stdout](original-export/driver.stdout) are preserved.

The Driver exited 0 in 106.33 seconds, within its 180-second Job and 185-second independent observer bounds. The [original observer](original-export/observer.json) records drained pipes, disposed exact process, stopped owned executables, no pending custody and removed inner runtime. The serial capture used preflight inode `126867980` and offset `908168`, then copied exactly 376,073 subsequent bytes (SHA-256 `5a8a0b59...`) before cleanup. The [decoder](original-export-readback.json) verified 223 ordered frames through END and 16 original files totaling 186,383 bytes against their offsets, lengths and SHA-256 hashes. The [journal check](journal-readback.json) validated all eight length/CRC32 states through REMOVED with payload exit zero. The guest [closure readback](guest-closure.png) showed the exact inner runtime absent and no named Runner/Driver process.

The exact guest outer scope `n-6c165808` was checked for reparse entries and removed. A separate [guest readback](guest-retirement-confirm.png) queried the same exact path at a new prompt and returned `False`. Host `sdc` was restored to its original ISO, foreign `sdb` was left intact, and the owned host ISO and stage were removed after live/inactive attachment, exact fuser, hash and link checks; see [host cleanup](host-cleanup-readback.json). The retained toolchain, public build and unrelated VM media were preserved.

This result covers the executed native Windows 1.77.2 f32 float cases only. It does not prove every feature combination, fault path, exact linker/SDK files selected by Rust, zero-test paths or full release acceptance. The installed Windows Kit Lib `10.0.26100.0` remains an inventory observation. The independent combined review is recorded in [combined review](combined-review.md).
