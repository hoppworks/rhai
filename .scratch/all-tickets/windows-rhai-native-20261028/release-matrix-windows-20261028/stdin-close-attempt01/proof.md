## Result and scope

The real Rhai `spawn` test starts a child, supplies 1 MiB of input, and independently reads the child's readiness receipt after its real stdin pipe held 12,288 bytes. The test opens the exact child process handle and verifies it is live before releasing it. The child records its intent and closes the real stdin handle. The public `try_wait` reports a typed `ProcessCause::Io` with operation `write child stdin` and `BrokenPipe`; the report's exit agrees with the independently signaled child handle and has no cleanup diagnostics. A second `try_wait` through a cloned public handle observes the cached error type, operation and kind.

The original [wrong control](original-export/run/.scoped-evidence-f1bb4250721146ecbb8a04e3562c329c/runtime/stdin-close-wrong.log) failed with exit 101 at the deliberate inverse error assertion after the pipe and process readback. The restored [GREEN](original-export/run/.scoped-evidence-f1bb4250721146ecbb8a04e3562c329c/runtime/stdin-close-green.log) passed 1/1; both used the same executable. The control calibrates presence of the expected error, not each report field or cached-error field. Buffered input is observed; a separate kernel-pending overlapped write is not claimed. The child's close-intent and resulting OS error support this case; no independent inspection of the child's handle table is claimed.

The [original serial slice](serial-original.bin) covers inode `126890480`, offsets `1163524–1504058`, 340,534 bytes, SHA-256 `161f7940d25260b349715ac530c8ae8b25e7bdf4406e101f29db85434d013e10`.
