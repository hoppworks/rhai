# Native Windows child handle drop policies

The public Rhai `spawn` returned two cloned handles to a gated real child. After the first handle dropped, the child wrote an acknowledgement to a fresh challenge. With `kill_on_drop=true`, dropping the final handle caused its exact independently opened Windows process handle to signal exit 1. With `kill_on_drop=false`, the child acknowledged a separate challenge after final drop and then exited 0 after explicit release. These observations establish survival until each acknowledgement and the observed direct-child exit; they do not establish uninterrupted future survival, output draining, supervisor or permit retirement.

Two distinct deliberately wrong challenge-survival assertions failed with Cargo 101, after exact child-exit observation and guard disarm. Restored full `sys_process_report` and `sys_process_windows` tests passed 7 + 17.
