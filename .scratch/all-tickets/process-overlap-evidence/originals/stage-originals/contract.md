# Process overflow/deadline overlap proof contract

This package proves the public `OutputLimit` cause when readable stdout overflow and an expired run deadline are observed during the same ordinary process-supervision step. It exercises DirectChild and Managed modes separately through the public API. Each child writes an independent acknowledgment; the receipt binds its PID, `/proc` start ticks and process group, confirms deadline expiry and an actual stdout-readable poll, records the overflow decision, exact child reaping, and owner closure.

The producer runs two timeout-first ordering controls, one per mode, each expected to fail only at the assertion `overflow must win over the simultaneously expired deadline`; it then restores the frozen source and runs both public regressions green. Each is a separate fully-qualified `cargo test --exact` command under the private Rust 1.77.2 toolchain and locked dependency set. No elapsed-time-only readiness or sleep-only acknowledgment is accepted.

The timeout-first control moves the existing expired-state cleanup block after the successful poll and immediately before the stdout-readable branch. The root-owned local source-order probe independently confirms poll-before-timeout-before-read, unchanged source byte length, and mutant SHA-256 `53ce5a454661ffd08e6f3d0a9bbac15c8ccd8f1ea397c042b777a066be756b23` against this exact source revision. That is static mutation evidence only; none of the four native commands has run yet.

The producer independently checks the bytes it actually wrote against that mutant hash before either timeout-first run. The collector requires the producer's injected-source hash receipt, binds every fixture ledger row to its exact raw command receipt and enforces readiness, expired deadline, readable poll, reap, and owner closure. The expected `/bin/sleep 30` fixture command is labeled as expected; it is not presented as an observed cmdline. Identity rows normalize numeric PID/PPID/PGID/start ticks before equality and require strict positive start ticks. Collection also checks all seven ordered setup/control commands, exact controlled environment and cwd (including `TMPDIR`, `TMP`, and `TEMP` at `<runtime>/tmp` as set by `run_scoped.py`), private runtime direct-child ownership, raw Rust/Cargo version outputs and host, periodic sample/maxima/cap reconciliation, and the 510/540-second export budget. The export checks before, between, and after individual copies and reports that one copy cannot be preempted. Fresh closure independently reconstructs the child/group set from hash-bound raw receipts and verifies the corrected `subprocess.run` transport call.

`recipe-probes.py` exercises the actual collector predicates and closure transport with deterministic inputs. Its valid cases pass; altered identities, fixture readiness/closure fields, mutant hash, runtime, command cwd and temporary-path, tool version, and resource count/maxima/caps are rejected. It also tests strict producer `/proc/<pid>/stat` parsing. These probes are local recipe validation, not native acceptance.
