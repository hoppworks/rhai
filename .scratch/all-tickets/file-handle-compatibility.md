# `sys` file-handle compatibility investigation

**Source baseline (observed):** first-party [rhai-fs](https://github.com/rhaiscript/rhai-fs/tree/1c1455c26ab1070d65fd3ad5dc363095eed6dc3f), immutable HEAD `1c1455c26ab1070d65fd3ad5dc363095eed6dc3f` (`Cargo.toml` version 0.1.5). The implementations are [`src/file.rs`](https://github.com/rhaiscript/rhai-fs/blob/1c1455c26ab1070d65fd3ad5dc363095eed6dc3f/src/file.rs), [`src/path.rs`](https://github.com/rhaiscript/rhai-fs/blob/1c1455c26ab1070d65fd3ad5dc363095eed6dc3f/src/path.rs), and feature declarations in [`Cargo.toml`](https://github.com/rhaiscript/rhai-fs/blob/1c1455c26ab1070d65fd3ad5dc363095eed6dc3f/Cargo.toml). Local scope is [phase 4](../../docs/sys-package-plan.md#6-phases), [D6/D12](../../docs/sys-package-plan.md#2-decisions), and [ticket 06](../stdlib-wayfinder/issues/06-compatibility-release.md).

**Observed contract:** `open_file(path)` is equivalent to `open_file(path,"w+")`: read/write, create, preserve existing contents (no truncate). Modes are `r`, `r+`, `w`, `wx`, `w+`, `a`, `ax`, `a+`, `ax+`; invalid mode falls through to OS `OpenOptions` with no access bits and errors. Path strings are converted to `PathBuf`; overloads also accept `PathBuf`. Handle type is `Shared<Locked<File>>`; `sync` selects a write lock, otherwise `borrow_mut`. `read_string([len])` and `read_blob([len])` read from current cursor; omitted or zero length means up to EOF, bounded by engine `max_string_size`/`max_array_size` when nonzero. String reads require valid UTF-8 and error otherwise; blob reads preserve bytes. `write` accepts string, and with indexing enabled blob; both call one `Write::write`, return bytes written (partial writes are possible). `seek(pos)` seeks from start, clamping `pos <= 0` to zero; `position()` reports cursor. Read/write/seek errors become string-backed Rhai errors. The crate declares `no_index`, `sync`, and `metadata`; blob support is cfg-omitted under `no_index`. No explicit close operation exists: handle lifetime/drop owns closure, and cloned shared handles refer to the same file/cursor.

**Proposed compatible subset:** add `open_file(path[, mode])`, `read_string([len])`, `read_blob([len])` where supported, `write(string|blob)`, `seek(pos)`, and `position()` using a shared locked file handle. Preserve signatures, mode behavior, cursor semantics, one-write return count, string UTF-8 errors, and implicit drop close. Apply `SysConfig` root confinement and read/write grants at open time; return the established catchable `SysError` for denied/I/O failures. Under `no_index`, omit blob overloads; under `sync`, retain shared locking. Do not claim existing `rhai-fs` enforces confinement or access policy.

**Decisions ticket 06 must settle:** the five phase-4 names alone do not specify open modes/default or whether `open_file(path)` truncates; rhai-fs default is `w+` (create, no truncate), unlike common create/truncate expectations. Confirm whether all nine modes are accepted and how write/append grants interact with `r+`, `w+`, `a+`; whether an open handle remains usable after its path is removed/replaced; whether an explicit close is desired (upstream has none); whether `read_blob`/blob `write` are unavailable under `no_index` or need another byte representation; whether to preserve upstream negative-seek clamp and partial-write count; and how `read_string` handles invalid UTF-8 and engine size limits in the confined package. Ticket 06's feature matrix must specifically gate/test `sync`, `no_index`, `metadata`, and integer modes: handles are `Shared<Locked<File>>`, blob APIs are excluded only by `no_index`, documentation is built with `metadata`, and positions/counts use Rhai `INT` conversions that can fail on overflow. No upstream `no_float`/`only_i32` specialization was observed in this source; test `only_i32` for conversion behavior rather than assume it.

**Exact acceptance cases (proposed):** (1) default `open_file` on missing and existing files creates without truncating existing bytes; verify independent host read-back. (2) exercise each documented mode for create/existing/read/write/append/exclusive-create outcomes and deny writes on read-only roots before mutation. (3) from nonzero cursor, omitted/zero and positive-length text/blob reads return expected bytes, advance cursor, honor engine limits, and invalid UTF-8 string read errors while blob read round-trips it. (4) string/blob writes return actual written count and a subsequent seek/read confirms bytes; test append mode, partial/error path as feasible. (5) seek negative/zero/positive and position match stated contract. (6) cloned handle shares cursor and stays valid until last handle drops; after drop, host can reopen/read file; test no explicit close. (7) denied outside-root open and mode-based write leave protected file unchanged. (8) compile and run applicable cases under `sync`, `no_index`, `metadata`, `only_i32` (blob assertions excluded only in `no_index`); document any intentionally unsupported combo. These extend—not replace—the plan's existing R6 documentation requirement.
