# `sys` file-handle compatibility investigation

**Source baseline (observed):** first-party [rhai-fs](https://github.com/rhaiscript/rhai-fs/tree/1c1455c26ab1070d65fd3ad5dc363095eed6dc3f), immutable HEAD `1c1455c26ab1070d65fd3ad5dc363095eed6dc3f` (`Cargo.toml` version 0.1.5). The implementations are [`src/file.rs`](https://github.com/rhaiscript/rhai-fs/blob/1c1455c26ab1070d65fd3ad5dc363095eed6dc3f/src/file.rs), [`src/path.rs`](https://github.com/rhaiscript/rhai-fs/blob/1c1455c26ab1070d65fd3ad5dc363095eed6dc3f/src/path.rs), and feature declarations in [`Cargo.toml`](https://github.com/rhaiscript/rhai-fs/blob/1c1455c26ab1070d65fd3ad5dc363095eed6dc3f/Cargo.toml). Local scope is [phase 4](../../docs/sys-package-plan.md#6-phases), [D6/D12](../../docs/sys-package-plan.md#2-decisions), and [ticket 06](../stdlib-wayfinder/issues/06-compatibility-release.md).

**Observed contract:** `open_file(path)` is equivalent to `open_file(path,"w+")`: read/write, create, preserve existing contents (no truncate). Modes are `r`, `r+`, `w`, `wx`, `w+`, `a`, `ax`, `a+`, `ax+`; invalid mode falls through to OS `OpenOptions` with no access bits and errors. Path strings are converted to `PathBuf`; overloads also accept `PathBuf`. Handle type is `Shared<Locked<File>>`; `sync` selects a write lock, otherwise `borrow_mut`. `read_string([len])` and `read_blob([len])` read from current cursor; omitted or zero length means up to EOF, bounded by engine `max_string_size`/`max_array_size` when nonzero. String reads require valid UTF-8 and error otherwise; blob reads preserve bytes. `write` accepts string, and with indexing enabled blob; both call one `Write::write`, return bytes written (partial writes are possible). `seek(pos)` seeks from start, clamping `pos <= 0` to zero; `position()` reports cursor. Read/write/seek errors become string-backed Rhai errors. The crate declares `no_index`, `sync`, and `metadata`; blob support is cfg-omitted under `no_index`. No explicit close operation exists: handle lifetime/drop owns closure, and cloned shared handles refer to the same file/cursor.

**Proposed compatible subset:** add `open_file(path[, mode])`, `read_string([len])`, `read_blob([len])` where supported, `write(string|blob)`, `seek(pos)`, and `position()` using a shared locked file handle. Preserve signatures, mode behavior, cursor semantics, one-write return count, string UTF-8 errors, and implicit drop close. Apply `SysConfig` root confinement and read/write grants at open time; return the established catchable `SysError` for denied/I/O failures. Under `no_index`, omit blob overloads; under `sync`, retain shared locking. Do not claim existing `rhai-fs` enforces confinement or access policy.

**Compatibility table (observed, proposed, or decision):**

| Area | Pinned-source observation | Classification for `sys` |
|---|---|---|
| `open_file` modes/default | `open_file(path)` selects `w+`; mode strings and `OpenOptions` flags are explicit at `src/file.rs:31-82`. `r+`, `w+`, `a+` permit writes; `r` does not. `wx`/`ax` use `create_new`. | Keeping these names and semantics, including no-truncate default, is ordinary compatible-subset preservation. Grant checks may reject a requested mode. A different default/mode set is a genuine divergence to decide. |
| close | No close function in file module; ownership is `Shared<Locked<File>>` (`src/file.rs:27-30`); dropping the last shared owner drops the underlying `File`. | Implicit final-drop close is preservation; adding explicit close is a new API choice, not required by compatibility. |
| blob/`no_index` | Blob module has `#[cfg(not(feature = "no_index"))]` (`src/file.rs:257-258`); blob `write` is also there. | Omitting blob functions under `no_index` preserves upstream behavior. Exposing another byte API is a divergence. |
| negative/nonrepresentable length | Read code branches on `len == 0` and `len > 0`; negative values reach the last arm, where `usize::try_from(len)` fails, then attempts `usize::try_from(INT::MAX)` (`src/file.rs:167-193,277-304`). If that fallback conversion fits `usize`, it resizes to that amount; there is no explicit clamp-to-zero. With `only_i32`, values outside i32 cannot be arguments; positive lengths fit `INT` and platform `usize` conversion/fallback applies. | Preserve this behavior for exact compatibility; explicitly rejecting negative lengths or treating them as zero is a genuine behavioral divergence. |
| seek and count overflow | `seek(pos <= 0)` selects offset 0. Positive positions convert to `u64`; returned `u64` cursor uses `TryInto<INT>` and reports formatted conversion error on overflow (`src/file.rs:11-16,225-236`). `position()` uses the same conversion (`241-245`). String and blob writes return one `Write::write` count through that checked conversion (`205-217,333-342`). | Negative seek clamp and checked overflow errors are preservation. Under `only_i32`, position/count greater than `INT::MAX` yields conversion error, not wrapping. |
| size limits / `unchecked` | Reads allocate at most `max_string_size` / `max_array_size` when nonzero (`src/file.rs:169-193,279-304`). Rhai documents 0 as unlimited; these APIs are absent under `unchecked` (`src/api/limits.rs:1-2,281-321`). Upstream rhai-fs call sites are not cfg-gated and still call getters. | In checked builds, zero means unlimited and nonzero bounds each read buffer. Exact `unchecked` compatibility is unresolved: do not claim the API works or limits are ignored; the upstream call sites reference getters Rhai omits under that feature. |
| metadata | `metadata` is an independent feature for generated package documentation; no file semantics branch on it (pinned rhai-fs `Cargo.toml`). | Supporting docs under `metadata` is ordinary feature support, not a script-semantic owner decision. |

**Genuine ticket 06 decisions:** whether the `sys` subset changes the upstream mode/default/seek/length/error behaviors, adds explicit close, or exposes bytes under `no_index`; whether an open handle remains usable after its path is removed/replaced; and whether/how `unchecked` is supported given the observed source incompatibility. Preserve the remaining listed upstream behavior by default as the meaning of “compatible subset.”

**Exact acceptance cases (proposed):** (1) default `open_file` on missing and existing files creates without truncating existing bytes; verify independent host read-back. (2) exercise each documented mode for create/existing/read/write/append/exclusive-create outcomes and deny writes on read-only roots before mutation. (3) from nonzero cursor, omitted/zero and positive-length text/blob reads return expected bytes, advance cursor, honor engine limits, and invalid UTF-8 string read errors while blob read round-trips it. (4) string/blob writes return actual written count and a subsequent seek/read confirms bytes; test append mode, partial/error path as feasible. (5) seek negative/zero/positive and position match stated contract. (6) cloned handle shares cursor and stays valid until last handle drops; after drop, host can reopen/read file; test no explicit close. (7) denied outside-root open and mode-based write leave protected file unchanged. (8) compile and run applicable cases under `sync`, `no_index`, `metadata`, `only_i32`; verify `INT` conversion error when position/count exceeds `INT::MAX` where practical. `unchecked` is a separate compatibility/build question because pinned calls access Rhai limit getters omitted by that feature; do not claim it works without resolving that cfg interaction. Blob assertions are omitted only under `no_index`. These extend—not replace—the plan's existing R6 documentation requirement.

**Review disposition:** this report supplies source facts, not acceptance of upstream
bugs as the `sys` contract. In particular, the negative-length allocation fallback
needs a deliberate decision: propose rejecting negative lengths before allocation
rather than reproducing an attempt to allocate `INT::MAX` bytes. The existing
checked/unchecked limit API split is independently confirmed in this repository's
`src/api/limits.rs` at source revision f7aed036; it must be handled explicitly.
Open-mode defaults, shared cursor, final-drop close and no_index blob omission can
be preserved as ordinary compatibility choices without reopening their basic scope.
Ticket 06 remains open for genuine divergences and release gates.
