# Native Windows bounded project-command composition

Status: **accepted for one real Cargo metadata command inside the existing public Windows Job custody path**. The [combined independent review](combined-review.md) passed this narrow criterion with the host-retirement limit stated below. This is an execution prerequisite. No Rhai Engine integration test, file/process/TCP product assertion, release matrix or full A–F criterion is accepted here.

## Export, correction history and retirement

- Initial console preparation had an unquoted hash-expression parser error, then PowerShell execution-policy rejection of direct `.ps1` execution. Neither reached the native Driver. The corrected, hash-guarded ScriptBlock entry ran the native command once; `attempt01/dispatch-v2-before-enter.json` records the host UTC launch and COM1 offset. The command and media were source-reviewed and hashed before that launch. The first native run ended after an export-inventory guard counted the 437 frozen source files: 442 recursive `run` files / 17,941,357 bytes exceeded the **64-file/16-MiB export cap**. A read-only guest query showed the actual observer had accepted Driver exit 0. Cargo was **not rerun**.
- The separate read-only exporter (`attempt01/ExportProjectOriginals.ps1`) was independently source-reviewed, guest-parsed, hash-guarded and run against the retained originals. `attempt01/serial-original.bin` contains **223 sequential frames**, ten original files / **201,438 bytes**, all reconstructed with their guest SHA-256 and strict sequence/length checks (`decode-original-export.py`, `attempt01/original-export-readback.json`). Its serial SHA-256 is `c5ee47e90d2d5726e630fbb3c6e7f8b3df1edc33f168897a5870c31ca1894a3a`. The host verifier passed; the guest originals remained present during this step.
- The exact-scope cleanup had four **pre-delete** preparation failures, retained in `attempt01/retire-*-result.png`: the first executable manifest used PS5.1 property enumeration instead of array count; the next omitted the immutable evidence copy; then the snapshot manifest paths were incorrectly interpreted relative to the evidence root and subsequently as an empty `runtime` directory. The fresh guest inventory gave **888 files, 91 directories, 36,210,018 bytes**. The final manifest maps the snapshot's 438 SHA-pinned files under `run/.scoped-evidence-*/runtime/`. None of the four failed attempts emitted a PREPARED frame or deleted a guest file. Previous manifest/media versions and the first guard failure remain saved; counts were not reset.
- The independently reviewed final cleanup source and manifest were byte-read from the v6 ISO before use (`attempt01/retire-v6-media-readback.txt`). Manifest SHA-256 `ce6e0dac8f99c08871d713720498e947f758563f76eec97b647639adc3772cdc` binds all 888 file hashes, 91 derived directories, the successful independent verifier and COM1 readback. The guest validated exact owner/scope, no reparse or extra entries, all hashes, original Driver generation absence and no active owned executable/argv, then removed **only** `project-control-49243ecf52d64c609a876e3c52409500`. `attempt01/retire-v6-receipt.json` contains both COM1 PREPARED and COMPLETE records; a fresh guest query (`post-retire-readback-result.png`) returned `PROJECT=False PUBLIC=True FIXTURE=True`.
- The original VM `sdb` and `sdc` ISOs were restored (`attempt01/host-original-media-restored.txt`). `retire-owned-host-media.py` inventoried and removed only this control's 76-file / 9,303,350-byte host stage and eight now-unmounted owned ISOs; `attempt01/host-retirement-receipt.json` records every hash, absence and the unchanged original media. The accepted guest public and fixture build scopes remain for compatible work only within their original expiry **2026-10-25 19:14:01.279906 UTC**; no extension is inferred.
- **Host-retirement limit:** before unlinking, the script checked attachments on `rhai-win11-quality`, not every libvirt domain or process using those paths. Its `foreign_resources_touched=false` field is an emitted claim, not independent pre-delete host-wide proof. A later read-only scan of both available VMs and `/proc` found no current mount or open file/cwd/executable reference to this control's nonce (`attempt01/host-wide-post-retirement-readback.json`). This does not reconstruct all pre-delete usage. The accepted Cargo/guest result and exact path/absence receipt stand; historical foreign-use absence at host retirement remains unverified.

## Applicability

This proves that the accepted public Windows custody tools can launch one pinned real Cargo project command from a copied Rhai workspace with bounded Job/process/output/runtime ownership, truthful exit status, independent metadata readback, assertion sensitivity and exact cleanup. It does **not** compile Rhai on Windows, execute a real Rhai script through Engine/host to the OS, prove process/network/filesystem API behavior, cover other Cargo commands or meet the native Windows release profile matrix. These remain open in `../windows-runner-gate.md` and `../../../docs/sys-package-plan.md`.
