### Covered correction routes

For F4, preserve real stdout and stderr as separate originals. Build a parser input with valid target association, and label any derived order honestly. The original ordered regression fixture is a useful positive/negative oracle; the new realistic split-stream fixture must also pass. Simply reversing the concatenation is insufficient for multiple targets: all headers would then precede all summaries. One bounded option is to validate the stderr integration-header sequence and associate each successive stdout block ending in a libtest summary with the corresponding target, requiring exactly one block/header and its complete named inventory. Label this as derived target order, not captured chronology; retain all diagnostics and EILSEQ skip detection. Alternatively, capture target-specific receipts with explicit invocation target context while retaining build reuse and the existing finite package. Any event-capture approach must actually retain both original streams and handle cross-stream ordering; renaming concatenation is not a correction.

For F3, keep creating files only in the owned central runtime. Configure the root using one of the verified system-prefix spellings of the actual directory whose spelling is used by the script. For example, obtain the two spellings of `t.path().join("real")`, configure `fs_root(&var_real_root, FsAccess::Read)`, then read `var_real_root/a.txt` and `private_real_root/a.txt`. `prefix_alias(root.given)` then explicitly supplies the second supported spelling. Retain string inequality and exact canonicalization checks before Engine construction, the denied write and independent host readback. Existing ancestor-symlink tests already cover ordinary `link`/canonical traversal; if this particular test retains `link`, configure/read the same `link` spelling pair rather than mixing a configured `link` root with newly invented `real` prefixes. The nested-prefix test does configure roots in the verified prefix forms and is not affected by this first-test mismatch. Native canonicalization and execution remain unverified.

A test correction requires a new honest source/test freeze, archive digest and helper/contract/prep pins. A helper-only parser correction does not by itself invalidate unrelated production proof. Both remaining defects belong in one consolidated owner correction.
