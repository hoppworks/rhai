# Managed Unix scope completion

## Decision and limit

The smallest safe first correction is a shared **termination-submitted → signals-fenced → leader-reaped → scope-observed-closed** state machine. On Linux, a conservative completion barrier can use passive `kill(-original_pgid, 0)` observation after the exact leader has been reaped, accepting only `ESRCH`. Finish all nonzero group and direct-child signaling while the leader still pins identity; permanently prohibit any later numeric termination operation before releasing that pin. A reused PGID can then cause a conservative delay or error, but cannot cause a destructive signal. This read-only existence check is explicitly different from another termination submission.

This is suitable for one bounded launch68 correction and investigation. It is **not** a universal mechanism for returning normal success as soon as every member has terminated: zombie membership can keep the probe positive until an external reaper acts. Do not call that situation failed termination, invent a host-reaper requirement, or close the full managed contract merely because the ordinary init environment passes. The required behavior is stopped scope members before successful publication, exact direct-child reaping, and finished local I/O obligations. Reaping arbitrary nonchildren is not an accepted obligation or authority. The barrier supplies a stronger conservative certificate where available; its limitations remain an explicit acceptance item.

A successful group kill is insufficient even if the current failed PIDs prove to be zombies. The production source lacks a completion predicate independent of submission. Conversely, changing the failed assertion to a loose `ps` check alone would leave that production defect unresolved.

This answer is source review, not native acceptance. No code, builds, probes, Git state or other worktrees were changed.

## Concrete shared boundary

Store an original PGID and a private scope-close state in the retained `OwnerRecord`, and carry that state through `DriverToken` handoff. Keep submission, child exit, child reap, scope completion, capture cancellation and report publication separate. Suggested states are `Open`, `CloseRequested`, `SignalingFinished`, `AwaitingClosure`, `Closed`, and `Unresolved`. Direct mode has no group obligation.

1. Natural managed leader exit remains observed by exact `waitid(P_PID, WEXITED|WNOHANG|WNOWAIT)`. Cancellation requests the original group termination and independently terminates a still-owned direct leader, including a leader that moved groups. Preserve the accepted Darwin natural-zombie-leader EPERM exception only with its existing exact listing conditions.
2. A successful submission records submission, not `Closed`. Finish the sole allowed termination attempt and store its outcome while custody is intact. Do not send another nonzero signal after leader reaping, including through fail, drop, later explicit kill, or service recovery. Group errors and ECHILD retain answer06's safety fences; no guessed ownership recovery.
3. When signaling has safely ended, observe/reap the exact direct child nonblockingly. Set an irreversible no-further-signals flag before consuming the wait status. Do not use blocking `wait()` as a scope barrier. A non-consuming reap failure retains custody; identity loss quarantines it.
4. If the original close request already returned ESRCH while pinned, record that scope observation. Otherwise, after reap, observe original PGID existence with signal zero at bounded cadence. `ESRCH` permits the conservative `Closed` certificate. Success means still unresolved; EPERM is unresolved, not empty; EINTR yields/retries within the step budget; other failures become diagnostics. Never enumerate targets or send a signal based on this probe. A reused number may keep the record unresolved but cannot produce false closure while the original group still exists.
5. Successful normal publication and successful timeout certification require `direct_reaped && scope_closed && local_io_finished`. EOF or explicit capture cancellation determine capture flags separately. Apply this predicate to `supervise`, spawned terminal publication, `fail`, `PumpGuard::finish`, cleanup-worker retirement and unwind/drop handoff. An already-reaped child with an unfinished scope still needs a retained record; the current guard paths must not discard it.
6. Preserve the existing one-second foreground cleanup allowance rather than introduce an unbounded wait. On expiry or operational failure, return the existing typed Process error with available leader status, immutable capture facts and an explicit unresolved-scope diagnostic. Timeout is not certified true while closure is unresolved. Transfer scope-only records to the already-running service, which performs passive bounded observation and fair progress, survives package/client drop, and retires only when obligations finish. Never mutate an already-published error when later closure occurs.

For spawned handles, `wait(seconds)` remains an observation deadline; it may return unit while scope closure is pending. `try_wait` remains nonblocking. Explicit cancellation, output overflow and true final-clone drop enter the same close path. False final drop leaves the retained service supervising ordinary execution; natural leader exit then enters this same path. Direct mode behavior and intentional escaped-process survival remain distinct.

## Why not simply require every PID to disappear?

A terminated zombie has stopped executing but remains represented until its entitled parent reaps it. `kill(pid, 0)` does not reliably distinguish these facts. Linux pidfds can certify exact nonchild termination through poll readiness without giving wait authority; readiness without PIDFD_THREAD waits for the last thread to exit. They are good independent fixture evidence, not an automatic complete process-group inventory. [kill(2)](https://man7.org/linux/man-pages/man2/kill.2.html), [pidfd_open(2)](https://man7.org/linux/man-pages/man2/pidfd_open.2.html).

The original test may retain immediate ESRCH as an additional environment-specific assertion while evaluating the conservative barrier. For the portable contractual assertion, require each recorded exact member to be terminated at result observation, accepting a verified zombie/exit handle and rejecting running, sleeping, stopped, traced and uninterruptible live states. Keep eventual exact PID absence as independent fixture cleanup evidence. Replace the stronger immediate assertion only alongside this exact termination proof and the production completion boundary; never classify inaccessible/missing/ambiguous observations as terminated.

A member PID/PGID snapshot is not complete scope proof. `/proc` enumeration plus a second scan is not an atomic group snapshot; permission restrictions and concurrent forks/moves matter. A pidfd must be acquired and its identity/membership validated, not opened from an unchecked receipt after potential PID reuse. Fixture records can establish the finite fixture members; they cannot define production scope membership.

The conservative ESRCH barrier avoids this discovery problem but may depend on foreign zombie reaping. If a held-zombie fixture demonstrates only incomplete-cleanup errors despite stopped members, that closes a safety requirement, **not** the intended general normal managed completion requirement. Keep that requirement open. No silent success fallback, fixed grace sleep or assertion weakening is acceptable.

## Alternatives and platform implications

Do not mutate the embedding host's SIGCHLD disposition, call host-wide wait-any, or enable host subreaping. Subreaping changes orphan ownership for the calling process, not one library execution. [PR_SET_CHILD_SUBREAPER](https://man7.org/linux/man-pages/man2/PR_SET_CHILD_SUBREAPER.2const.html), [wait(2)](https://man7.org/linux/man-pages/man2/waitpid.2.html).

If completion independent of external reaping is required and the conservative barrier fails it, a separate per-execution supervisor with kernel-backed membership/exit observation is the viable architecture class to investigate. On Linux, an isolated subreaper can own/reap its descendants without taking the host's foreign children. It must remain outside the target group, preserve target status, establish supervision before target exec, retain escapees without signaling them, and expose an authenticated completion/error protocol. Subreaping alone is insufficient: live escaped ancestors can have descendants still in the original group, so `waitpid(-pgid)`/ECHILD alone does not prove all group members stopped. A stronger complete membership facility or a carefully proven tracking mechanism is still required. A cgroup can provide a different kernel scope, but replacing process-group semantics with it would change accepted escape behavior and require an explicit contract/deployment decision.

Do not implement a Rust supervisor loop inside `pre_exec` after a multithreaded fork. Current setpgid/fchdir-only pre_exec remains appropriately narrow. An execed helper requires a shipped, versioned executable and launch-authority/distribution review; the library cannot assume its host executable understands helper arguments. A raw-syscall-only fork supervisor would require independent unsafe/post-fork review and is not a small Rust-loop patch. No helper mechanism is declared proven by this answer.

The first conservative boundary needs no new dependency or Rust API beyond the existing optional libc edge and synchronization types; preserve core1.66 and sys1.77.2. Kernel features and visibility are separate from Rust MSRV. pidfd fixture proof requires explicit Linux5.3+ availability and a checked older-platform observation route or an honest unsupported proof result; no silent fallback.

macOS needs native verification of passive group probing and the existing exact-only-leader Darwin exception; do not generalize EPERM to success. A native complete group listing can support a platform-specific stronger predicate, but its truncation, identity and atomicity rules must be preserved. Windows retains its job-object boundary and requires independent active-job completion observation, not only termination submission or leader wait. This review does not certify either platform.
