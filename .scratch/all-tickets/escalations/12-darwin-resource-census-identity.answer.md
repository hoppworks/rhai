## Requirements and chosen technique

Acceptance requires real public Engine/OS behavior, intended failing controls, independent read-back and conservative resource/lifecycle evidence. It does not require a sampled short-lived process to survive until a separate `ps` completes. Identity must be supplied by the observation that establishes membership, rather than inferred from a later process with the same PID.

Apple's implementation collects process records before formatting their fields; it also obtains task information separately. A single `ps` invocation therefore removes the helper's inter-query identity race but is not an atomic kernel snapshot of membership and RSS. Preserve the periodic sampling qualification. ## PID reuse and independent cleanup

`lstart` is second-resolution text, and the current 48-bit digest does not create a unique kernel identity. Apple formats it from `p_starttime.tv_sec`. Same-PID reuse within one second and hashing collisions remain possible; neither PPID nor command fixes this. Call receipts exact observations of the returned row, not collision-proof lifetime handles. [Apple start-time formatter](https://github.com/apple-oss-distributions/adv_cmds/blob/main/ps/print.c)

For this finite package, the simplest conservative solution is to require **every recorded PID to be absent at independent cleanup**, irrespective of a changed start/command/PPID. The current readback allows a live PID with a different start digest; tighten that condition for the new package. A reused live foreign PID causes an honest inconclusive cleanup failure, never permission to signal it or claim absence. Retain all recorded groups and reject any remaining group member. Query errors, permissions, malformed output and unknown receipt fields remain failures. Reparenting or `exec` must not hide a survivor. Only exact owned runtime absence and exact real empty scope permit empty-directory retirement.

This deliberately conservative cleanup avoids unsafe reliance on second-resolution identity for successful closure. It does not prove that sampling saw every descendant, that a process could not escape custody, or that current PID absence reconstructs every historical lifetime. Existing outer supervision claims are unchanged. Do not broaden signals using census receipts.

If a collision-proof identity is separately required, stock `ps lstart` cannot supply it. Darwin exposes start seconds/microseconds in `proc_bsdinfo` and resident bytes in `proc_taskinfo`, combined in `proc_taskallinfo`; a reviewed native collector could use those fields. It still needs enumeration-race, errors, ABI and cleanup handling. That would be a larger implementation, not the simplest repair of this helper's current receipt contract, and is not recommended as an automatic second fallback. [Apple process-info structures](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/sys/proc_info.h)
