# macOS overhead launch custody

## Decision

Use one project-local custodian as the sole spawner and reaper, an anchored process group for each external command, direct Cargo execution, and a separate passive closure certificate for the frozen benchmark's finite escaped leaves. Do not launch the measurement at f7dab7934f7f7f42245ec23008fe8e2616606799. That source has neither the command custody nor the escaped-leaf certificate required below.

This is a bounded implementation route, not native acceptance. The existing responsible `macos_overhead_safeguards` context should implement it after root review. No production process changes, global runner changes, native launches, retries, or additional escalation chain are proposed. Root's subsequent update records actual native invocation count 82: Linux82 failed before runtime creation on its missing copied `agentskills.pyguard` dependency. This macOS analysis consumes no slot and does not reset that count or Linux history.

The essential distinction is that Cargo-group closure proves closure of confined build/test hosts; it does not terminate a Managed fixture in its new group. The frozen fixture has a separate, narrow termination mechanism: loss of the test host closes its capture readers and stdin writer. Its finite output writes then complete or fail, stdin reaches EOF, and its main thread finishes or panics. This argument needs native confirmation and complete passive readback; it cannot be replaced by reaping the intermediate Python driver or checking sampled descendants.

## Custody invariants and shutdown

The custodian remains outside every command group. Each group is created before untrusted command code is released. The gate and anchor are exact unreaped children; anchor liveness is checked non-consumingly before the sole nonzero group signal. A live anchor pins the original PGID. Numeric IDs obtained from snapshots never grant signaling authority.

For normal completion, observe command leader exit without reaping, then close residual confined descendants while the anchor still pins the group. For cancellation or client INT/TERM/KILL, client socket EOF, protocol error, resource stop, or deadline, stop accepting launches and run the same shutdown path. Send at most one SIGKILL to the anchored command group, then irreversibly disable further nonzero group signaling before reaping the gate/command and anchor. Do not use TERM followed by a later group KILL: TERM can destroy the pin. Exact still-unreaped direct children outside a group may be killed individually, then reaped. Treat ECHILD, missing anchor readiness, ABI failure, and ambiguous ownership as custody errors, not recovered authority.

After signaling and exact reaping, passive original-PGID absence is a conservative confined-group certificate. Permission failure is not absence; surviving zombies are not permission to claim runtime cleanup. No further group signal is permitted after the pin is released. Waiting for passive closure can fail at its bound without weakening acceptance.

The control process must never SIGKILL the custodian. It can kill the exact client to test client interruption while the custodian remains responsible. Custodian SIGKILL/crash recovery is not supplied by the historical anchor protocol and is not claimed by this route. A terminal directed at the wrapper must route cancellation to the custodian; avoid placing it in a terminal foreground group that the control kills indiscriminately.

## Complete escaped-leaf readback

Do not certify this from a one-second ancestry ledger, `capture-record.txt`, argv matching, pipe EOF, or a fixed grace sleep. All can miss a short-lived or pre-record fixture, and EOF is not a generic process termination certificate.

Implement a bounded native process-list reader using the installed Darwin SDK's reviewed `libproc` declarations. After the confined build/test spawners are proven closed, obtain a complete, nontruncated process list including zombies, inspect same-user executable paths and process identities, and conservatively track every process whose image is the private runtime test executable, any other executable under that runtime, or `/usr/bin/true`. Include all same-user `/usr/bin/true` processes rather than trying to infer which one belongs to the benchmark. Foreign matches only delay/fail certification; never signal them. Any inaccessible same-user row, unknown executable state, truncated buffer or unresolved query is an error. A row that disappears during lookup needs a fresh complete listing, not classification as an unrelated process. Do not unlink private executables until this readback finishes.

The finite-source argument makes this listing useful: after every possible test host is stopped, remaining benchmark children cannot create further processes. A pre-exec Managed child is already present and has the private host image; it can only become the same private fixture executable or `/usr/bin/true`. Both transitions remain in the candidate set. Thus there is no late birth of an owned leaf after the closed-spawner boundary. Repeated bounded listings observe deaths/exec transitions; they do not manufacture general recursive process-tree tracking. Require candidate absence, including zombies, and final original-group absence before deleting the runtime. Record fixture PID/start observations as supplementary readback, never as signal targets.

Apple's current [process-list implementation](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/proc_info.c) collects live and zombie PIDs under its process-list lock and can stop when its buffer fills. Its [libproc declarations](https://github.com/apple-oss-distributions/xnu/blob/main/libsyscall/wrappers/libproc/libproc.h) expose the list/path query interfaces. This supports the proposed reader, but does not certify the installed Darwin ABI/version. Check installed headers and matching kernel source semantics before freezing the adapter; use explicit buffer capacity/returned-length checks and finite growth limits. Keep UID/path changes between list and lookup conservative; do not silently discard a candidate on inconsistent metadata.

There is one important launch prerequisite still uncovered by the supplied source: build confinement. Rhai's own `build.rs` only reads/writes files, but the complete locked dependency build scripts and invoked toolchain have not been audited here. Group custody covers descendants that stay in the group. A dependency build script that escapes and forks arbitrary executables invalidates the finite-leaf argument. The responsible context must review the exact resolved build scripts/tool commands for group/UID escape and descendant spawning, recording the source references and confinement assumption. If that cannot be established, this route cannot certify interrupted build-tree closure; stop before the measurement. Do not silently expand the passive candidate set and call that complete general supervision. This is a concrete unresolved prerequisite, not permission to substitute retention for closure.

## Finite meaningful controls

Freeze the source and control contract before execution. Use one attempt per case, no retry. Controls are separate from the benchmark: do not invoke `process_scope_overhead_measurement` to obtain their readiness or count their partial samples as measurement. A small companion control host can link the frozen Rhai library and call the public API against the unchanged frozen `process_fixture`; its source lives outside the archived measurement source. Its build and execution consume the same declared package resources. Record any changed companion host explicitly.

| Case | Injection precondition and action | Mandatory result |
| --- | --- | --- |
| Setup interruption | Actual Git archive or extraction gate/anchor registered, command released and independently observed running; TERM the exact harness client | Custodian stops requests, anchored setup command closes, exact children reap, complete readback succeeds, runtime disappears |
| Build interruption | Actual Cargo plus an independently observed compiler/build child, not merely a live Python process; KILL the exact harness client | Same closure, Cargo/build group absent; build confinement prerequisite already satisfied |
| Active Managed capture interruption | Companion host invokes real public Managed capture with frozen zero-input, 8 MiB/stream fixture; observe fixture record, live fixture/new PGID, and both capture streams active; freeze the exact directly owned host if needed, recheck live capture, then KILL that exact host | Host reaped, its pipe ends closed, escaped fixture stops without numeric nonchild signaling, candidate listing proves absence, runtime disappears |
| Deadline/resource cleanup | A gate-held directly owned workload establishes live resources; trigger the same real timeout/resource-stop cleanup entry | Closure receipt and expected failure status, no later launch, exact cleanup and runtime absence |
| Registration and observation RED | Pure protocol/state controls omit anchor readiness or final escaped-leaf certificate, and simulate incomplete/truncated/inaccessible readback | Launch withheld or cleanup acceptance rejected; restore checks and observe the matching pass |

Use explicit readiness, not sleeps. The active-capture case must reject an already completed fixture or idle/absent stream as an invalid injection. External stop/readback may win or lose a scheduling race; losing it is a failed control, not proof and not permission to rerun. Do not modify the measured timer or fixture to make readiness easier. The companion's own cancellation behavior must not be used as the evidence for abrupt host death. Record all native allocations/launches in the existing cause history before dispatch; root determines the concrete finite slot allocation. This answer consumes none.

Independent root readback checks exact wait statuses, signal timing while pinned, no later nonzero group operations, closed command descriptors, complete escaped-leaf observations, sentinel survival in a distinct directly owned group where used, runtime device/inode and absence, and preserved failure logs. Intentionally interrupted controls have expected nonzero statuses but can pass their closure contract. Successful benchmark acceptance additionally requires Cargo=0, exactly 120 validated records, frozen manifests, and the same full closure receipt.

## Time and resource allocation

Start the scoped deadline before runtime creation. All phase deadlines derive from that one monotonic origin. Reserve time rather than adding cleanup budgets after expiry.

| Envelope | Allocation |
| --- | --- |
| Outer 600 s | Scoped package at most 585 s; remaining 15 s for wrapper/export verification and independent readback |
| Scoped 585 s | Harness work ends by 560 s; at most 15 s for group stop/reap and escaped-leaf closure to 575 s; at most 5 s for evidence/receipt to 580 s; at most 5 s for exact runtime deletion/readback to 585 s |
| Driver 580 s | Setup, direct Cargo, parsing/export and its closure report all finish by 580 s; stop accepting normal work at 560 s |
| Aggregate Cargo 540 s | Accumulate actual Cargo elapsed time across the declared finite package; any command also ends by work deadline 560 s. Available Cargo time is the smaller of remaining aggregate allocation and remaining work time |

A slow setup reduces available Cargo time; 90 s archive plus 90 s extraction plus 540 s Cargo is not an allowed schedule. Use `min(local_phase_cap, remaining_phase_time)` everywhere. Proposed command-local close allocation is 5 s exact reap, then the remaining closure allocation for passive group/leaf absence. Snapshot/query/export operations receive deadlines too. Resource sampling remains approximately one second, jobs=2, descendants<=16, sampled RSS below 2 GiB, storage below 1,572,864 KiB. Count all custodian-owned commands/anchors and escaped candidates in resource observations; declare any controller overhead separately without exceeding the caps. No cap or cumulative history resets.

Each interruption control is a separately declared short case within its own outer/scoped maximum; it does not receive an additional 585 s appended to a running benchmark package. Keep related build products within one owned runtime when reused and export only needed evidence before deletion. Do not run a whole benchmark merely to prove setup interruption.

No userspace protocol can guarantee both a hard wall-clock exit and successful OS termination/reaping under arbitrary scheduler stalls, blocked kernel operations or custodian death. At a bound, unresolved custody/closure is an honest failed case with retained runtime and owner, never acceptance. This limitation does not waive the required passing controls: the measurement remains unlaunched until source prerequisites and native interruption controls actually establish closure. Likewise, answer08's accepted Unix incomplete-cleanup error does not turn an interrupted overhead runtime into a cleaned runtime.
