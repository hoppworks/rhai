## Smallest safe repair candidate

Keep self-inclusive job membership, kill-on-close, no breakaway, every bound, the setup injection and immutable marker checks. After preserving/flushing the primary diagnostic, make failure disposition explicitly terminate the **exact retained job** with a reserved nonzero status, before any ordinary failure-path `CloseHandle(job)`. Use a small positive status (for example 97) distinct from the ordinary 0/17 controls and not `STILL_ACTIVE`; this avoids unsigned/signed presentation ambiguity. Apply this to the shared failure path, not only `SetupFailureControl`, so the outer harness also cannot silently report successful failure teardown.

`TerminateJobObject(job, status)` documents that its supplied exit value is used for job members and termination includes nested child jobs. Unlike a close, it supplies an explicit status. It includes the reporting shell, so do not require code after successful self-inclusive termination to execute, and do not claim that shell can perform postmortem accounting. Preserve the exact handle and kill-on-close fallback through process teardown. If termination returns failure, capture the error and use the existing fail-fast custody fallback; never unwind to the interactive caller with the owned handle live. Account separately for a failure before self-assignment: an empty-job termination cannot terminate the controller, so that path must still close its exact handle and return an explicit controller failure. [Microsoft TerminateJobObject contract](https://learn.microsoft.com/en-us/windows/win32/api/jobapi2/nf-jobapi2-terminatejobobject).

Do not clear kill-on-close on failure, terminate only the ping PID, accept a zero control status because a marker exists, or move the observer into the job it must inspect after death. Keep successful owner-only accounting, successful close checks and timer disposal/drain behavior. Keep failure diagnostics outside disposable build output until exported. This is a repair recommendation requiring implementation and review, not verified executable code.
