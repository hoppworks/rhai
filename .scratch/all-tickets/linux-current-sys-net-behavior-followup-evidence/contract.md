# Native Linux optional-MSRV sys/net behavior package

This prepared package covers selected current-source Rust/Cargo 1.77.2 behavior on native Linux x86_64. The immutable production input is source `1ca21e32eed2aa40287ba7e1282000add1dd49c7`, archive SHA-256 `8251e0429d51ffd330e7eac596a1513d836e43e549ca761852cafc642a2a8155`, and accepted v3 `Cargo.lock` SHA-256 `2ba4b3a0807e32b613ff2e972b893c3fd2e0923fd91803611963f09e93265425`. The stage script explicitly stages those bytes, this helper and contract, and the exact scoped runner package under `/root/rhai-linux-current-sys-net-behavior-1ca21e32-20261002-followup1`.

The helper provisions Rust/Cargo 1.77.2 only in the invocation's private `RUSTUP_HOME` and `CARGO_HOME`, using the already-present `/root/.cargo/bin/rustup` with `--no-self-update`. It invokes Cargo from the extracted private archive with the staged accepted lock and `--locked`. It rejects any frozen source `.cargo/config` or `.cargo/config.toml` override and any config placed in private `CARGO_HOME`. All extracted source, generated test binaries, target output, caches, HOME, temp files and run logs stay under `AGENT_RUNTIME_DIR`; `TMPDIR` is the scoped runner's private runtime path. Cargo uses two jobs, incremental compilation off and debug info disabled. The source archive and lock are checked before use, the lock and complete Cargo manifest hash map are read before and after each row/control, and original source bytes remain untouched in the repository.

One Cargo invocation per positive row reuses the same private target directory and runs its selected integration targets with `--test-threads=1`; concurrency explicitly created by a test remains part of that test. The tests exercise the real Engine through public Rhai scripts against host filesystem/environment policy and real loopback TCP peers. The combined test independently reads back its host file and joins its peer before checking data. No mocks substitute for the Engine, filesystem or TCP peer. Five pre-existing source assertion seams provide meaningful wrong expectation controls and are run first with deliberately wrong expected values: sys file read, regular TCP peer read, regular TCP peer write, combined host-file readback, and the explicit-handle `net,no_object` peer. Each control must exit 101 and show that its exact named test ran, panicked in its selected `tests/<target>.rs` source (with an optional numeric test-thread ID, as emitted by some Rust versions), and failed an assertion containing the intended wrong-value data. The combined host readback uses a Rust custom `assert!` message that omits the generic assertion prefix, so only that exact named test may satisfy the assertion marker through its fixed message plus exact actual and wrong expected values. This rejects compile/setup status 101, zero tests, another failing assertion, and a control that reports the restored expectation. Positive rows must have status 0 and a successful result summary for every selected target, with at least one test passed and zero failed, ignored, measured, or filtered tests. The positive Cargo invocation merges stderr and stdout into one chronological output stream because Cargo writes `Running tests/<target>.rs` markers to stderr while libtest writes its summaries to stdout. The parser requires each selected target exactly once regardless of Cargo scheduling order, and keeps the last summary within each target boundary because `sys_env` and `sys_fs` include child-test fixtures that can emit nested summaries.

The selected source test suite may use test-runner processes and test-local threads as host machinery; it does not invoke Rhai's `sys_process` API, process fixtures, script examples, native custody harnesses, or native process measurement. Existing Linux examples proof `e33b842f` already demonstrates the standalone `sys` and `net` documentation examples with real host file and TCP peer readback and their wrong-expectation controls. This package does not repeat those example runs; it adds integration-test API behavior at Rust 1.77.2 and the listed feature combinations.

The helper records its private runtime and its own and scoped-supervisor PID/start identities before stage validation or any subprocess. Missing identities are durably recorded and stop execution before commands. The wrapper uses the existing scoped runner, 600-second outer limit, exact stage and unique project scope. It retains launcher/runner/helper/supervisor identities, command statuses and logs, exports evidence before runtime cleanup, then independently reads back exact process identities/groups and runtime absence before removing only the exact empty scope. Interrupt requests use the stage-local cancellation file; the helper preserves failure status and exports only within its original deadline. Unknown process state fails closed and preserves the scope for readback.

The finite limits are outer 600 seconds, helper 540 seconds including setup and export, work 510 seconds with a 30-second export reserve, Cargo jobs 2, at most 16 descendants, and sampled private-runtime storage/RSS hard stops of 2,097,152 KiB with a preemptive storage stop at 1,572,864 KiB. Measurements are periodic sampled maxima, not continuous peaks or reservations. Do not increase these caps or treat them as whole-release resource acceptance. Native process invocation count remains 84; no invocation 85 is allocated. Native process acceptance remains separate.
