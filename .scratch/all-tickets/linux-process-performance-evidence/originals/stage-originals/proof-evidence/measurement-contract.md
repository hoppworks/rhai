## Fixed run

Run one Linux x86_64 invocation with Rust/Cargo 1.77.2, features `testing-environ,sys`, and the exact test target `linux_process_performance`. Run the lightweight `measurement_controls_reject_corruption` test first, then the ignored `direct_managed_measurements` test. The test uses the public `Engine`, registered `SysPackage`, public `spawn`/`run_raw`, and real OS processes. It uses no test mock for process execution or `/proc` observations.

For starts, take five paired samples. At each index use Direct then Managed for even indices and Managed then Direct for odd indices. Each sample starts the same `/bin/sh` fixture through public `spawn`; the child writes its PID to a same-directory pending file and atomically renames it into the readiness path, then remains alive until a release file appears. After the external rename helper has returned, the held shell writes a separate PID acknowledgment; the host waits for both complete records and confirms both PIDs equal `Child.id`. This keeps the transient helper out of the managed-group census. The reader retries incomplete or absent readiness only until the fixed five-second deadline. Start latency is measured from immediately before `Engine.eval(spawn(...))` until the host reads and validates that readiness record. Record the actual mode order and raw nanoseconds. The process ID in the record must equal the public `Child.id`; read `/proc/<pid>/stat` start ticks and process group independently. Release and wait through the public handle, then verify that exact identity is absent.

For capture, take three paired samples with the same alternating order rule. Public `run_raw("/usr/bin/head", ["-c", "1048576", "/dev/zero"])` must return success, status zero, complete stdout, and exactly 1,048,576 zero bytes. Time the complete captured run, including process start and collection; report bytes divided by that elapsed time as captured-run throughput, not transfer-only throughput. Preserve each raw timing.

For retained resources, once per mode run the same held shell child after its readiness receipt. Sample immediately before spawn, while the exact fixture identity is live and held, and after release plus public wait and Engine drop. Report separately: the known held fixture process identity, its `/proc` thread and descriptor counts, parent harness thread and descriptor counts before/live/after, and process-group membership count. Direct-child mode inherits the test process group, so its group-wide count is context only and is not labeled owned. Managed mode must report the fixture's dedicated group. Start/capture rows preserve sample index, mode order, and raw elapsed nanoseconds; resource rows preserve mode, PID, start ticks, process group, readiness latency, and the live/closed counts. Do not infer causal package overhead from these samples.

The byte-integrity control performs one separate public-Engine 1 MiB capture, validates the real payload, then proves a copy with its last byte changed is rejected. The resource control starts one separate live public Child fixture, independently reads its PID/start-tick identity and real thread/descriptor counts, then proves a deliberately zeroed descriptor count is rejected. Lightweight census controls also prove malformed/unreadable `/proc` rows and directory iteration errors fail closed while an actually vanished PID is skipped. Both process fixtures are released/reaped and logged separately before the measured samples. Controls run before the measurement and have named expected diagnostics; they do not rerun the full sample suite. The test contains fixed counts only; it does not adapt repetitions, payload size, or scope after seeing results.
