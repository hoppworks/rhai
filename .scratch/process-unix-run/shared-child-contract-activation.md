# Prepared shared `Child` contract fixture

`tests/fixtures/sys_process_shared_child_contract.rs` is a source-only fixture for the planned public `spawn`/shared `Child` API. It is not Cargo-registered yet because the public Engine currently has no `spawn` function. The development RED harness injects it into private source, so existing integration tests remain buildable. No unregistered source is accepted evidence.

The first test-first invocation selects only `spawn_returns_while_large_stdin_is_blocked_and_wait_snapshots_are_stable`. It must reach the public Engine call and fail with `Function not found: spawn`; this is a development-toolchain RED only. It proves no OS process behavior and does not satisfy MSRV/release verification. The fixture and remaining lifecycle tests are prepared source, not activated acceptance evidence. Do not activate the full suite until direct-child and descendant cleanup custody is independently implemented and proven.

Once production implements the documented API, activate by adding `#[path = "fixtures/sys_process_shared_child_contract.rs"] mod shared_child_contract;` to `tests/sys_process.rs`, under the same `all(feature = "sys", unix, not(feature = "no_index"))` gates. The entire focused suite uses `--features testing-environ,sys,sync` and the project scoped runner. Preserve the exact child records, process ownership and cleanup receipts.

Assertion mapping:

- `spawn_returns_while_large_stdin_is_blocked_and_wait_snapshots_are_stable` uses an 8 MiB stdin payload. The real child publishes readiness before reading, and input and exit releases are separate. The test requires prompt `spawn`, verifies input is still pending, checks finite `wait(0.02)` returns unit while stdin remains blocked, releases input, then checks final `wait` and `try_wait` maps. It mutates one returned map and checks later snapshots are unchanged. The child independently records its PID, bytes consumed, validation result and exit; the controller verifies ESRCH. A bounded exact-Child controller watchdog remains in the runner's inherited process group. This guard does not claim escaped-descendant custody; those lifecycle tests remain inactive until their cleanup ownership is established.
- `nonfinal_child_clone_drop_keeps_the_real_child_available` drops one `Dynamic` alias, then requires a fresh nonce challenge/reply through the remaining alias.
- `final_drop_honors_both_kill_on_drop_policies` checks bounded direct-child absence when the final client is dropped with host `kill_on_drop=true`; with `false`, it proves the child answers a fresh challenge after final-client drop, then releases it and checks eventual reaping.
- `sync_waiter_can_be_cancelled_through_another_shared_child_handle` (`sync` only) races a public timed waiter with cancellation through a cloned handle and requires bounded waiter completion, final wait and direct-child ESRCH. Its start-channel receipt shows the waiter is about to call `wait`, not that it has entered the blocking part before cancellation.

Readiness and completion records use temp-write plus rename. The fixture directory is inside `AGENT_RUNTIME_DIR`; Rust Drop removes the exact directory, and the scoped runner removes the private runtime if its hard watchdog interrupts the test. All fixture waits are bounded. The source remains uncompiled and unrun, and every shared `Child` behavior remains open.
